# Midoku Web

- Always push work straight to `main`. Do not create side branches.
- Mobile-only PWA built with React, Vite and TypeScript. Run `npm run build` before pushing to confirm it compiles.
- Boxy design: square corners everywhere, dark theme, coral accent (`--accent` in `src/styles.css`). Icons come from Hugeicons (`src/components/Icon.tsx`).
- Suwayomi: the server address (and optional basic-auth login) is entered in Settings and kept on the device; the app calls the server directly (Suwayomi allows any origin, without cookies). No Vercel proxy. `src/data/suwayomi.ts` is the client; without an address the app shows sample data from `src/data/mock.ts`.
- Suwayomi is read-only for reading data: it supplies titles, chapters, pages and extensions. Never write reading state to it, and ignore its own. The exceptions are extension management (install, update, uninstall on the source page's ⋯) and source fetches it does anyway.
- Cloudflare: when FlareSolverr can't pass a source's check, the source page (globe button, ⋯, or the error notice) opens Suwayomi's own WebView (`webviewUrl` → `/api/v1/webview#<url>`) in a new tab; solving the check there leaves the cookies on the server.
- Midoku's own data (library, tabs, reading progress, read/bookmark/removed marks) lives in Supabase project `Midoku-web` (`src/data/db.ts`), with row-level security. There are no accounts: one built-in user (`owner@midoku.invalid`), and the app password screen (`PasswordGate` in `src/components/Lock.tsx`) signs in as it. The password is asked again every 10 days per device; it can be changed in Settings → Privacy. Schema changes go in `supabase/migrations/`. Without a server address the sample data is kept in localStorage.
- Server titles use ids `s<mangaId>` and chapters `c<chapterId>` in the app; the database keys titles by source id + manga url and chapter state by source chapter url.
- Library organisation: tabs (categories) the person files titles into, plus Reading, All and saved-filter tabs, in a swipeable pager. A title can be in several tabs. On a server, tabs and filing are stored in Supabase; the Reading tab is a list kept by hand (`entries.reading_pos`). A title that holds nested titles is shown as a series.
- Navigation is a custom screen stack (`StackRoutes` in `src/components/Nav.tsx`): each screen is its own scrolling layer, the previous one stays mounted underneath. Do not go back to the View Transitions API; it misrenders on iOS Safari. The iOS edge swipe is the system's own; history steps the app did not start are not animated again.
- Head tags: web manifest, no `apple-mobile-web-app-capable`, but `apple-mobile-web-app-status-bar-style: black-translucent` so screens run under the status bar (tops pad with `--safe-t`). With it, iOS sizes the viewport short by the status bar when the page has no height of its own (every screen is a fixed layer), leaving a band under the tab bar; `html { min-height: calc(100% + env(safe-area-inset-top)) }` prevents that. iOS doesn't let a web app hide the status bar, even in the reader.
- Each deploy gets a new service worker version (`vite.config.ts`); the app offers "Restart to update" when one is waiting.
- Midoku collection semantics carry over: entries can nest titles, link several sources, hold chapter versions, inserted and split chapters, and removed chapters that can be restored. Reading actions resolve the physical source chapter.
- The reader renders only pages near the current one; keep it that way so very long chapters stay light.
- Offline: database writes go through an ordered outbox (`flushWrites` in `src/data/db.ts`) that survives reloads and is sent when back online. The library snapshot and opened titles (kept 3 days after last opened; longer while they have downloads) live in Cache Storage (`src/data/cache.ts`). Downloads are Midoku's own (`src/data/downloads.ts`, cache `midoku-downloads`), never Suwayomi's. The service worker serves downloaded pages and caches covers/icons (`midoku-images`); it must not delete those caches on deploy.
- Linked sources merge into one chapter list (`mergeChapters` in `src/data/library.ts`): same chapter number = one slot with versions, the main source's chapter is read. New chapters: `checkUpdates` asks Suwayomi to fetch chapters of followed sources (on launch every 6 h, or the Library button). Titles whose server id stops matching are found again by source id + url (`resolveManga`).
- Chapter versions: a slot's `alts` are its physical chapters (one per linked source); the version read can be chosen per chapter (chapter sheet or the reader's title) and is saved as `preferred` on that chapter's state. Page layouts are stored in `chapter_splits` (`breaks` = first page of each later part, `excluded` = pages left out) and edited in the page-thumbnail picker (`PageSplitter`); `visibleChapters` shows them as parts / trimmed chapters; reading state stays on the whole chapter (`toPhysical` in the store). Inserted chapters (`inserted_chapters`) come from any title or source.
- Title page: details as a grid of facts; tabs, sources and series live in the ⋯ menu; long-press (or right click) a chapter for its sheet; long-press the library (bookmark) button to pick tabs. Long-pressable things and sheets are `user-select: none`. Loading, empty, caught-up and error states use `src/components/Status.tsx`.
- Edited details (title, author, description, cover) live in `entries.custom` and are put over the server's by `applyCustom` (`src/data/library.ts`); the server's values stay in `entry.original`. Picked cover pictures are shrunk to a JPEG data URL. Never send a custom cover through `assetUrl`.
- Library selection (Select button): Group (nested series or merged title, `GroupSheet` in `src/components/LibraryTools.tsx`), Tabs, Remove. A nested series made in Midoku has no source: id `l<dbId>`, children ordered by `entries.position`. Merging keeps the first title's row and moves the others in with the `merge_entries` RPC (sent through the outbox): their sources become later `segment`s; `mergeChapters` merges each segment and puts them one after another, numbered by position (`renumber` = Chapter 1, 2, 3…).
- Library header has only Search, Filter and ⋯. The ⋯ sheet holds Check for new chapters, Select titles, Add to Reading, Clear Reading, Random from the whole library, Bookmarks, History and Find duplicates (same normalised name or same source title). Keep the header to those three buttons.
- Updates feed (`src/data/updates.ts`, `useUpdates`): shared by Home (bell badge = updates newer than when Updates was last opened on this device, `midoku.updatesSeenAt`; a preview of the newest unread ones) and the Updates screen (long-press a row: read, mark read/unread, download, open title; Mark all read per day). Reloaded after each update check. A chapter that got new pages also shows "+N pages" in the title's chapter list until it's opened (`newPages`, from `chapter_states`).
- Downloads screen (`/downloads`, Settings → Manage downloads): what's downloading (cancel), failed (retry), and saved chapters by title with sizes.
- `store.entry()` reads the latest state, so code that awaited `loadEntry` sees the loaded chapters.
- Updates (`/updates`, Home's bell): newest chapters of every followed source in one server query (`getRecentChapters`), Midoku's read marks on top, plus chapters that got new pages, last 60 days, by day. New pages: `checkUpdates` re-fetches the page list of each followed title's newest chapter when the server had fetched it before; more pages are saved as `chapter_states.pages`/`pages_before`/`pages_grew_at` (`notePageGrowth`, partial upsert so progress is kept).
- Home with a server shows Popular from one source (picked there, else the source most of the library comes from).
- Images fetched with a login are kept as blob URLs in memory (`Art.tsx`, ~60 MB of unused ones) so screens and reader pages don't flash on the way back. Sources, Search (with its last search) keep their lists for the session.
- History (`/history`, `src/pages/History.tsx`; also from Home's clock button): one row per title, its latest read chapter, grouped by day. With a server it is `chapter_states.read_at` + `chapter_label`, written by `setProgress`; `clear_history(entry)` RPC removes one title or all. Sample mode keeps it in localStorage (`src/data/history.ts`). Resume opens that chapter, or the next one if it was finished.
- Reader modes: Webtoon, Paged and Right to left (paged, reversed). The device default is in Settings; a title's own mode is `custom.reader` (reader top bar → Reading mode). Paged: tapping the left or right 30% turns the page (reversed for right to left), the middle shows/hides controls. Paged pages zoom with pinch or double tap in the middle (`Zoomable`); while zoomed the pager doesn't turn pages. Webtoon zooms the whole strip (pinch or double tap): the strip is scaled inside a sizer of the scaled size so the scroller pans it natively. A single tap waits ~260 ms so a double tap doesn't toggle the controls.
- Trackers (AniList, MyAnimeList…) are deliberately not planned; don't add them.
- Chapters can be moved (`chapter_states.position` → `order`/`number`, `sourceNumber` keeps the original). "Add to entry" (chapter sheet, or Select → Add to) adds chapters to another library entry as inserted chapters, like native Midoku: search the library, pick an entry, the name defaults to its next chapter and its number places the chapter. There is no clipboard.
- Integration testing: `scripts/test-server.json` holds a temporary Suwayomi test login and the app password (`appPassword`). Tests that read chapters write to the real library: undo progress and history they leave behind.
- Screens other than Home and Library are lazy-loaded; the service worker precaches every built asset so they open offline.

- Chapter list: a plain list by default; the grid/list button by the chapter list (a title's `custom.thumbs`, no other setting) shows a grid of thumbnails, like native Midoku. A thumbnail is a page of the chapter (first page, a part's first page, or `chapter_states.thumb` = `page:N`) shrunk on the device to 240 px JPEG and kept in Cache Storage `midoku-thumbs` (`src/data/thumbs.ts`, made only for chapters on screen, two at a time), or a picked picture stored as a data URL in `thumb`. Long-press a chapter → Edit thumbnail; long-press a page in the reader's Pages grid; title ⋯ → Reset thumbnails.
- Reader bottom bar: Chapters (list sheet), previous, page slider, next, Bookmark (bookmarks the page you're on); the Pages button floats above Bookmark (page grid, tap to jump). Grids of page images use `LazyImage` so they load as they scroll in.
- Migration (title ⋯ → Migrate, `migrateSource`): pick the title on another source; it is linked, reading state (read, page, bookmark, hidden, moved, thumbnail) and page layouts are copied to the new source's chapters by number, it becomes the main source and the old one is unlinked. Chapters the new source lacks keep their state on the old urls only.
- The whole app is `user-select: none` (iOS long-press otherwise selects the screen); only form fields are selectable. Sheet rows must let long text shrink (`min-width: 0`); `tsconfig` has `noUnusedLocals`.
- Reading status is automatic only: Unread (nothing read or started), Reading, Completed (`statusOf`). No hand-set statuses; old `custom.status` values are ignored and dropped on the next edit. Mark a whole title read/unread with `markEntry` (title ⋯, Edit details, or long-press in Library); it includes nested titles.
- Library: series (titles holding titles) are ordinary cards in the grid, marked by a books icon in the cover's top-right corner (`CoverCorner`); titles inside a series get a layers icon. Long-press a card for its options (continue, open, mark all read/unread, tabs, select, remove).
- Bottom nav: Home, Library, Search, Sources, Settings (Settings is a tab, not a Home button). Home hides its Updates section when there is nothing unread.
- Page bookmarks: `chapter_states.marks` (whole-chapter page numbers), toggled by the reader's bookmark button (`toggleMark`), listed in title ⋯ → Bookmarks; opening one goes to `/read/<entry>/<chapter>?page=N`. The chapter-level bookmark stays in the chapter sheet; the Bookmarked filter counts both.
- Migration in bulk: Library → Select → Migrate (`BulkMigrateSheet`): pick a source, each title is searched there by name, first result picked (tap to change or skip), titles already on it are skipped, then `migrateSource(…, quiet)` runs one by one.
- Chapter filter sheet (sliders by the chapter list): sort by number or upload date, filter by linked source and scanlator (any version of a slot counts).
- Source filters: a source page's sliders button opens the extension's own filters (`getSourceFilters`, `SourceFilters.tsx`): checkboxes, include/exclude tags, selects, sort, text, groups. Only changes from the defaults are sent (`filters` on `fetchSourceManga`, as a SEARCH).
- Reading tab: a list the person keeps by hand, like native Midoku (`entries.reading_pos`, lower first; `addToReading`, `removeFromReading`, `moveInReading`; sample mode keeps `state.queue`). Add via long-press → Add to Reading, the title's ⋯, or Library ⋯ → Add to Reading (picker). Its shuffle button (bottom right, Reading tab only): tap = random title from Reading; long press, or an empty Reading list = random from the whole library.
- Get new chapters: only titles with a followed source are checked (`checkUpdates`, the Updates feed). New titles and links start unfollowed (`entry_sources.following` default false). Pick them on Updates → bell (`FollowSheet`: Add titles, Stop all, remove one); `setFollow` follows a title's main source or stops all its sources. Unfollowed linked sources still contribute the chapters the server already has.
- Source settings: the source page's gear (or ⋯ → Source settings) when `isConfigurable`; `getSourcePreferences` / `setSourcePreference` (saved on the server at once). Extension repositories: Sources → database button (`getRepos` / `setRepos`, Suwayomi `settings.extensionRepos`); a GitHub repo page is turned into its `raw/repo/index.min.json`.
- Bookmarks screen (`/bookmarks`, Library ⋯ → Bookmarks): every bookmarked page by title (`loadPageMarks`), opened with `openBookmark`. On a title page a "N bookmarked pages" strip shows them; the Bookmarked filter lists bookmarked pages above bookmarked chapters.
- Title page cover: tap = full-screen cover (`CoverViewer`) with Save (share sheet / download) and Edit. A series made in Midoku shows only a cover picked for it (no fallback to a child's).
- On-device page cache (`src/data/pageCache.ts`): chapter page lists are kept 3 days (localStorage `midoku.pageLists`, keyed by server + chapter; `chapterPages` in thumbs.ts reads it, the reader asks afresh on Try again or when the server's page count differs). Page images the reader and page grids load (`RemoteImage persist`) go to Cache Storage `midoku-pages` up to Settings → Storage's size (default 300 MB, oldest dropped). Clear cache clears it with thumbnails.
- Library tabs: hold a tab you made (or a saved filter) to rename or delete it. A title inside a series that left the library shows on its own; Reading lists only library titles.
